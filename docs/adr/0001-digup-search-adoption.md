# ADR-0001: DigUp を参考にした検索改善の採用方針

- 状態: **提案**（2026-10-14）。実装の採用判断と PR レビューは未完了。
- 関連: [#6](https://github.com/ysogabe/memo-collector/issues/6)、[#7](https://github.com/ysogabe/memo-collector/issues/7)、[#8](https://github.com/ysogabe/memo-collector/issues/8)、[#9](https://github.com/ysogabe/memo-collector/issues/9)、[#10](https://github.com/ysogabe/memo-collector/issues/10)、[#11](https://github.com/ysogabe/memo-collector/issues/11)。
- 根拠: [commit 固定の比較調査](../research/digup-comparison.md)、[段階的な実装計画](../plans/digup-search-evolution.md)。

## 背景

memo-collector は ContextRecord とテキスト/画像の融合ベクトルを保存する。現行 Core ML 埋め込み、256 次元の vDSP 検索、非同期 triage、状態シグネチャと再試行はすでに実装済みである。一方、URL/識別子の照合、検索根拠、安全な索引世代の切替、日本語の継続評価が不足する。

DigUp の実コードは、複数 segment の意味検索と FTS を組み合わせ、別プロセスで抽出/推論する。FTS は日本語専用ではなく、融合も RRF ではない。Q8_0/768 次元と Core ML/256 次元の速度差には、ランタイム以外の差も含まれる。

## 提案する決定

1. **Core ML + 現行融合ベクトルを基準として維持する。** 推論方式の変更は #8 の同条件比較を経て別の実装変更として判断する。
2. **評価基盤の最小版を #7 より先に用意する。** 合成 ContextRecord ID、複数正解、正解なし、言語・識別子などのタグ、dev/holdout を固定する。Recall/HitRate/nDCG/MRR の定義を明記し、旧 PoC 0.933 と区別する。
3. **独立した検索経路と根拠付き結果を設計として採用する。** #7 の隔離 DB で日本語 tokenizer、短語/識別子照合、RRF、必要なら DigUp 型加点を比較する。製品への融合方式採用は実測後に判断する。
4. **#9 は索引世代を DB 内で管理し、旧世代を保持して切り替える。** 入力 version/hash の条件付き書き込みを先行させ、#5 の編集競合も同じ保存契約で解消する。モデル manifest の改良は #3 と責任を分ける。
5. **OCR を検索本文へ追加するのは、ガード済み索引と外部出力の契約を満たしてから。** 元画像から秘密を含む OCR を保存・MCP excerpt に返す構成は採用しない。まず注釈/タイトル/URL/app の評価を進める。
6. **プロセス分離は #10 の計測と小さな PoC で判断する。** 同一プロセスとの比較、IPC timeout、再起動上限、永続 job、入力 version、親終了を扱う。新着キャプチャを優先し、過去分の再索引にだけ電力/温度 policy を適用する。

## 選択肢と理由

| 選択肢 | 判断 | 理由 |
|---|---|---|
| DigUp のモデル・検索式・FTS・helper を一括移植 | 不採用 | 日本語、融合入力、MCP の画像ガード、旧索引保持を満たす根拠がない |
| 現行ベクトル検索だけを継続 | 基準線として維持 | 既存品質を比較できるが、識別子/根拠/再構築の不足は解消しない |
| 評価 → 検索 PoC → 原子的な索引 → 必要な本実装 | 推奨 | 採否を分けて判断でき、各 Issue の成果物と既存設計を活かせる |
| runtime の build が変わるたびに全再索引 | 不採用 | artifact の版とベクトル互換性を分け、固定入力の数値/順位回帰で確認する |

## 結果と代償

既存記録、融合検索、キャプチャ優先を基準に保ち、後続の比較を再現可能にする。旧世代の保存中は DB と一時ディスク使用量が増える。query encoder と active 世代の対応も必要になる。単に索引ポインタだけを切り替える設計では、旧モデルで旧索引を検索する契約を満たせない。

本 ADR は検索 API やテーブル名を確定するものではない。#7/#9 の結果とレビューで確定する。各 PoC が採用基準を満たさなければ、既存方式を維持して観測結果を残す。

## 検証と決定の更新

- #7: 同じ corpus/query/filter で現行・keyword・semantic・融合を比較。識別子と日本語の層別品質、ゼロ件誤検出、P50/P95、索引サイズ、ガードを確認。
- #8: 元重み/入力/次元/精度の差を明記し、text/画像/融合を別々に測る。アプリ ANE と MCP GPU は別の基準線とする。
- #9: 再構築と編集/削除/クラッシュ/設定変更が重なっても旧/新ベクトルが混ざらず、旧世代へ戻せることを障害注入で確認。
- #10: キャプチャの保存速度と耐クラッシュ性、総 footprint、復旧時間、低電力時の動作を現行と比較。
- #11: モデルを使わない品質/整合性 CI と、実モデル/性能の専用実行を分ける。しきい値を dev 側で固定して holdout を採否に使う。
