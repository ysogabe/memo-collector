# PoC レポート: ローカルモデルで Context Capture は成立するか

- 実施日: 2026-10-08 ／ 環境: Apple M3・24GB・macOS 27・Python 3.12・torch 2.14 (MPS)・transformers 5.19
- 計画と合格基準: [poc-plan.md](./poc-plan.md) ／ コードと生データ: [`poc/`](../../poc/)（`poc/results/*.json`）

## 結論

**条件付きで成立する。** 3 モデルのうち **d1-3B と EmbeddingGemma 2 は採用、d1-omni-600M は日本語用途では不採用**。秘密情報ガードはモデルではなく **Apple Vision OCR + 正規表現**で担う。

| 合格基準 | 結果 | 判定 |
|---|---|---|
| キャプチャ経路 p90 ≤ 2.0 秒 | STT + d1-3B 意図 + 埋め込みで **p90 1.64 秒**（p50 1.56 秒） | ✅ |
| 意図分類 ≥ 80%（未見データ） | **d1-3B 95.5%**（21/22）。d1-omni 54.5%、ルール 59.1% | ✅（d1-3B） |
| 秘密情報 再現率 ≥ 90%・誤検知 ≤ 20% | **OCR+正規表現 4/4・誤検知 0**。d1-3B は最良でも 3/4 | ✅（OCR） |
| 検索 Recall@3 ≥ 0.8（※事後に追加した基準） | **テキスト+スクショ融合 0.93**、テキストのみ 0.88、スクショのみ 0.80 | ✅ |
| 常駐メモリ ≤ 8GB（※事後に追加した基準） | 3 モデル同時常駐で **MPS 約 11GB** | ❌ → d1-3B をオンデマンドロードにして回避 |

## 1. 結果の詳細

### Q1. 日本語 STT（mlx-whisper large-v3-turbo）

| 指標 | 値 |
|---|---|
| 平均 CER（句読点除去後） | 7.4%（語彙プロンプトあり 7.35%） |
| 1 件の処理時間（音声 2.7〜7.5 秒） | p50 1.04 秒 / p90 1.09 秒 |
| 初回呼び出し（ロード込み） | 3.8 秒 |

誤りの多くは合成音声側の英単語の読み（Hermes→「HRMES」、OAuth→「OA、明日」、Thunderbolt→「TH、UNDERBOLT」）と、同音異義（以降/移行、基地/既知、使用/仕様）。**固有名詞の辞書登録（カスタム語彙）は製品要件**にする。

### Q2. 意図分類（todo / research / code / note / schedule）

| 方式 | 開発セット (30) | **未見セット (22)** | 1 件の遅延 |
|---|---|---|---|
| ルール（日本語キーワード） | 93.3% | **59.1%** | 〜0 |
| EmbeddingGemma 2 ゼロショット | 60.0% | - | 0.04 秒 |
| EmbeddingGemma 2 kNN（k=3, LOO） | 50.0% | - | 0.04 秒 |
| d1-omni-600M（テキスト・英語指示） | 53.3% | **54.5%** | 0.10 秒 |
| d1-omni-600M（テキスト・日本語指示） | 60.0% | - | 0.11 秒 |
| d1-omni-600M（**音声を直接入力**） | **16.7%**（全件 note に崩壊） | - | 0.28 秒 |
| **d1-3B（テキスト・英語指示）** | **83.3%** | **95.5%** | **0.31〜0.53 秒** |
| d1-3B（STT 結果を入力） | 83.3% | - | 0.57 秒 |
| d1-3B（STT + スクショ + メタ） | 70.0% | - | 10.1 秒 |

- **ルールは過適合する**。開発セットを見て書いたルールは未見データで 34pt 落ちた。会話の「最初は LLM すら不要」は日付抽出には当てはまるが、意図分類には当てはまらない。
- **d1-3B は STT の誤りに強い**（正解テキストと STT テキストで精度が同じ）。期限・日時の言及の有無も 93% で判定できた。
- **スクショを足すと精度が下がる**（83%→70%）。画面の内容に引っ張られて「note」に寄る。意図は**注釈テキストだけ**で判定する。
- d1-omni の音声エンコーダは英語の発話中心に学習されており、日本語音声からは意図を取れなかった。
- 確信度で足切りすると、d1-3B は閾値 0.7 で 83% を自動分類・精度 88%。残りは「未分類」のまま Inbox に置く運用と相性が良い。

### Q3. 画面種別と秘密情報の写り込み

| 方式 | 画面種別 (7 クラス) | 秘密情報 再現率 / 誤検知 | 1 枚の遅延 |
|---|---|---|---|
| d1-omni（画像のみ） | 42.9% | 0/4 / 0 | 1.1 秒 |
| d1-omni（画像 + アプリ名・タイトル・URL） | 85.7% | 1/4 / 0 | 1.1 秒 |
| d1-3B（画像のみ、1440px） | 78.6% | 2/4 / 0 | 11.1 秒 |
| d1-3B（画像 + メタ、1440px） | 85.7% | 2/4 / 0（閾値 0.4 で 3/4 / 1） | 10.2 秒 |
| d1-3B（画像 + メタ、720px） | 78.6% | 0/4 / 0 | 3.0 秒 |
| **Apple Vision OCR + 正規表現** | - | **4/4 / 0** | **0.21 秒** |

- d1-3B は `.env` の API キー（p=0.92）や `gh` のトークン（0.80）は拾えるが、**AWS のシークレットキー表示画面（0.17）を見逃した**。720px に縮めると 4 件とも見逃す。
- OCR+正規表現はパターンを知っている種類には確実。未知の形式のキーは拾えないので、**OCR を主、d1-3B を補助（「パスワードらしき画面か」の判定）**にする。
- 画面種別は、アプリのバンドル ID とウインドウタイトルからほぼ決まる。モデルで判定する必要は薄い。

### Q4. Context Inbox の検索（EmbeddingGemma 2）

| 検索対象 | 768 次元 R@3 / MRR | 256 次元 R@3 / MRR |
|---|---|---|
| 注釈 + アプリ名・タイトル・URL（テキスト） | 0.88 / 0.90 | 0.88 / 0.85 |
| **注釈 + スクショの融合ベクトル** | 0.88 / 0.90 | **0.93 / 0.95** |
| 音声のみ（STT なし） | 0.45 / 0.62 | 0.45 / 0.57 |
| スクショのみ（日本語クエリ → 画像） | 0.80 / 0.73 | 0.65 / 0.71 |

- エンコード時間: テキスト 0.04 秒、画像 0.77 秒、融合 0.77 秒、クエリ 0.03 秒。**保存時に裏でインデックスすれば検索は即時**。
- 「ビデオ会議の画面」「AWS のアクセスキー作成画面」のような**画面の見た目での検索**が日本語で通る。注釈を付け忘れたキャプチャも探せる。
- 同じ画面に付いた注釈同士の類似度 0.90、別画面 0.69。重複キャプチャのまとめ表示に使える。
- 音声のまま埋め込むのは不十分。STT を経由する。

### Q5. 常駐コスト

| 構成 | ロード時間 | メモリ |
|---|---|---|
| d1-omni-600M (fp16) | 2.9 秒 | MPS 1.2GB |
| d1-3B (bf16) | 6.2〜8.4 秒 | MPS 6.3GB |
| EmbeddingGemma 2 (bf16, 全モダリティ) | 6.2〜7.1 秒 | MPS 1.5GB |
| Whisper large-v3-turbo (MLX) | 初回 1.9〜3.8 秒 | プロセス RSS 約 2.0GB（Python 込み、単独実行時） |
| **3 つを同時常駐** | - | **MPS 約 11GB（ドライバ確保分）** |

d1-3B の 6GB が支配的。**常駐させるのは Whisper と EmbeddingGemma（計 3〜4GB 程度の見込み、要実測）にし、d1-3B は最初のキャプチャで読み込み、一定時間使われなければ解放する**。ロード 6 秒はキャプチャ経路に入れず、意図ラベルは保存後に非同期で付ける。

## 2. 推奨アーキテクチャ（PRD に反映済み）

```
⌥Space 押下 ─┬─ 前面アプリ / ウインドウ / URL 取得（Accessibility・AppleScript）
             ├─ ウインドウ単体スクショ（ScreenCaptureKit）
             └─ 録音開始（AVAudioEngine）
⌥Space 解放 ─── STT（Whisper turbo / 将来 FluidAudio）……約 1.1 秒
             └─ Context Record を保存 → トースト「保存しました」 ← ここまでが同期（≤2 秒）

非同期（保存直後に順に実行）
  1. 意図・期限の有無 …… d1-3B テキストのみ（0.3〜0.5 秒、確信度 < 0.7 は未分類）
  2. 秘密情報ガード …… Vision OCR + 正規表現（0.2 秒）→ 該当すればマスク対象に印を付ける
  3. 検索インデックス … EmbeddingGemma 2 融合ベクトル 256 次元（0.8 秒）

エージェントへの受け渡し時
  - 秘密情報の印があるキャプチャは、スクショをマスクするか人の確認を経てから渡す
```

元会話の「キャプチャ時は重い処理をしない」は守る。OCR とモデル推論は**保存後**に回し、外部へ渡す**境界**でガードを効かせる。

## 3. モデル別の判定

| モデル | 判定 | 使いどころ |
|---|---|---|
| **d1-3B** | **採用** | 注釈の意図・期限の有無（テキストのみ）。補助的に「パスワード管理・認証画面らしいか」 |
| **EmbeddingGemma 2** | **採用** | Inbox の検索（融合 256 次元）、重複のまとめ |
| d1-omni-600M | **日本語では不採用** | 英語 UI 向けの軽量版の候補として保留。音声直接判定は日本語で不成立 |
| Whisper large-v3-turbo | 暫定採用 | PoC 基準は満たした。FluidAudio（ANE）と比較して最終決定 |
| Apple Vision OCR | **採用** | 秘密情報ガードの主系 |

## 4. 限界と次の検証

- **ホールドアウトは完全な盲検ではない**。未見 22 件は、ルールだけでなく 3 方式すべての開発セットでの挙動を見た後に評価者自身が書いた。ルールに対しては未見だが、d1-3B に有利な文面に寄っている可能性は残る。
- **データが小さい**（30 / 22 / 14 件）。精度は ±10pt の幅で読むこと。特に未見セット 95.5% は 22 件中 21 件。
- **合成音声とモックの画面**。実発話（言い淀み・雑音・早口）と実画面では下がる前提。次フェーズで自分の声 100 件・実スクショで再評価する。
- **d1-3B の量子化版**（GGUF 等、13 種公開）は未検証。決定ヘッドを持つ特殊な構造のため、llama.cpp 系で同じ API が使えるかを確認する価値がある。使えれば常駐メモリ問題が解ける。
- `trust_remote_code` を使うため、モデル更新時はコード差分のレビューが要る（PoC では revision を固定）。
