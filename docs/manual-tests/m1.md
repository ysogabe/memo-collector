# 実機確認手順: M1「録って残す」（PRD F-01〜F-08）

Wave 2 wiring で、ホットキー → 撮影 + 録音 → 文字起こし → 保存 → トースト → Inbox の縦串をつないだ。
自動テスト（`scripts/check.sh` とアプリの単体テスト）はフェイクの部品で状態機械と保存の流れを確かめただけで、
**権限・実際のキー入力・マイク・画面・Whisper の実行はどれも未検証**。以下をユーザーが実機で確かめ、チェックと結果を書き込む。

部品単体の詳しい確認（ホットキーの方式、ブラウザごとの URL、スクショの対象ウインドウ、録音の音質など）は
[capture.md](capture.md) にあり、ここでは重複させずに番号で参照する。capture.md の診断関数はアプリのデバッグメニューから呼べる。

## 0. ビルドと起動

```zsh
cd /Users/yoshio/works/60-misc/memo-collector   # またはこのブランチをチェックアウトした場所
perl -e 'alarm shift; exec @ARGV' 2400 scripts/check.sh     # パッケージのテスト + アプリのビルド
codesign -dv --verbose=2 DerivedData/Build/Products/Debug/ContextCapture.app 2>&1 | grep -E "Authority|TeamIdentifier|flags"
#   Authority=Apple Development: sogabeyoshio.dev@gmail.com (3H5DM2CR45) / TeamIdentifier=PJH36NNFL6 / flags=0x10000(runtime)

# アプリの単体テスト（AppCoordinator の状態機械など。check.sh には入っていない）
(cd app && xcodebuild -project ContextCapture.xcodeproj -scheme ContextCapture -derivedDataPath ../DerivedData test)
```

### 起動（スパイクの Whisper を使う場合）

モデルの置き場は `CC_MODELS_DIR`（既定 `~/Library/Application Support/ContextCapture/Models`）。スパイクで取得済みの
Whisper（1.5GB）を使えばダウンロードを省ける。**モデルルートは `stt` まで**（その下に `whisperkit/` がある）。

```zsh
APP=$PWD/DerivedData/Build/Products/Debug/ContextCapture.app
open -n "$APP" \
  --env CC_MODELS_DIR=/Users/yoshio/works/60-misc/memo-collector/spikes/runtime/models/stt \
  --stdout /tmp/cc-m1.log --stderr /tmp/cc-m1.log \
  --args --debug
```

- **起動する前に、動いている ContextCapture をメニューの「Context Capture を終了」で止めておく**。`-n` は 2 つ目を立ち上げるので、
  同じ DB を 2 プロセスで開き、ホットキーも「ほかのアプリが ⌥Space を使っています」と誤って出る（`-n` は `--args` を効かせるために付けている）。
- **`open` で起動すること**。ターミナルからバイナリ（`Contents/MacOS/ContextCapture`）を直接実行すると、マイク・画面収録の
  許可がアプリではなくターミナル側に付く（TCC の「責任のあるプロセス」がターミナルになる）。
- `--debug` を付けるとメニューにデバッグ項目が常に出る。付けなくても **⌥ を押しながらメニューバーのアイコンをクリック**すると出る
  （反映が次に開いたときになることがある。そのときはもう一度開く）。
- 試験用にデータを分けたいときは `--env CC_DATA_DIR=/tmp/cc-m1-data` を足す（既定は `~/Library/Application Support/ContextCapture/`）。
- スパイクのモデルには manifest が無いが、ファイルが揃っていればそのまま読み込む（取り直さない・書き込まない）。
  `CC_MODELS_DIR` を付けない場合は、オンボーディングの「ダウンロードを始める」で Hugging Face から約 1.5GB を取得する
  （オンボーディングの文言は「合計 約 5GB」だが、M1 で取るのは文字起こしモデルだけ）。
- ログ: Console.app でサブシステム `dev.ysogabe.ContextCapture` を絞り込む（カテゴリ capture / hotkey / models / store）。
  Instruments の os_signpost で区間 `pressToRecording` / `releaseToSaved` も見られる。
- アプリを止める: メニューの「Context Capture を終了」。

### 権限を付ける順番

1. **マイク**: オンボーディングの「権限」で「システム設定を開く」→ OS のダイアログで許可（これが無いと次へ進めない）
2. **画面収録**: 同じく「システム設定を開く」→ システム設定で ContextCapture を ON → **アプリを終了して起動し直す**
   （許可はプロセス内でキャッシュされ、再起動まで反映されない）
3. **アクセシビリティ**: 「システム設定を開く」→ ON（再起動は不要のはず。ウインドウタイトルと、Carbon が ⌥Space を拒否したときの CGEventTap に使う）
4. **オートメーション**: 事前には付けない。Safari / Chrome / Arc / Edge を前面にして初めて ⌥Space を押したときに、ブラウザごとに OS が尋ねる
5. モデルの準備 → 「準備ができました」→「使いはじめる」

### 失敗の経路（起こしにくいもの）

- 文字起こしの失敗 → 「文字起こしに失敗しました」「音声は残して保存しました。」と [再試行]。起こし方の例: Whisper の読み込み前に
  モデルフォルダを一時的に別名にする（`STTError.modelNotFound`）。[再試行] で保存済みの音声を読み直して文字起こしし、成功すれば「保存しました」に変わる。 [ ]
- 解放の取りこぼし → 120 秒押しっぱなしとみなして保存する（保険）。 [ ]

## 2. 計測（PRD §10）

デバッグメニューに直近 20 件の p50 / p90 が出る（「計測値をコピー」で値の一覧もコピーできる）。他の重い処理を止めた状態で、
1-3 を 20 回以上（1〜3 秒の発話）繰り返して書き込む。**最初の 1 回は Whisper の読み込み待ちが入るので、起動から 1〜2 分待ってから**測る。

| 指標 | 目標 | p50 | p90 | n |
|---|---|---|---|---|
| 押下 → 録音開始（`recorder.start()` の完了。HUD の表示はこの直後） | ≤ 150ms | | | |
| 解放 → 保存（トーストの直前） | p90 ≤ 2000ms | | | |

- 計測の起点はどちらも OS のキー入力の時刻（ハンドラが動いた時刻ではない）。
- 解放 → 保存の大半は文字起こし（空いた状態で p90 1.69 秒、負荷時 2.4〜6.6 秒の実測あり。計画書 §7）。

## 4. 保存の形式（M1 の実装メモ）

- スクショ: **HEIC**（品質 0.85）。PRD F-03 は WebP だが、この macOS の ImageIO は WebP を書けない（読めるだけ）。書けるようになれば自動で WebP を選ぶ
- 音声: **WAV**（16kHz モノラル 16bit。録音器の出力をそのまま。PRD §7 の例は m4a）。既定 7 日で消える
- 記録の `guard.status` は `pending` のまま（秘密情報ガードは M2）
