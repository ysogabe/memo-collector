## 0. ビルドと起動

```zsh
cd /Users/yoshio/works/60-misc/memo-collector   # またはこのブランチをチェックアウトした場所
perl -e 'alarm shift; exec @ARGV' 3000 scripts/check.sh   # パッケージのテスト + アプリのビルドとテスト

APP=$PWD/DerivedData/Build/Products/Debug/ContextCapture.app
open -n "$APP" \
  --env CC_MODELS_DIR=/Users/yoshio/works/60-misc/memo-collector/spikes/dev-models \
  --stdout /tmp/cc-m2.log --stderr /tmp/cc-m2.log \
  --args --debug
```

- `spikes/dev-models/` に 3 モデル（`whisperkit/`・`embeddinggemma-2/`・`d1-3b-text-q8/`）が揃っている。d1 と whisper は manifest の無い
  シンボリックリンクだが、ファイルが揃っていれば取り直さず・書き込まずにそのまま使う。
- 試験用にデータを分けるなら `--env CC_DATA_DIR=/tmp/cc-m2-data` を足す（MCP も同じ `CC_DATA_DIR` で登録する）。
- ログ: Console.app でサブシステム `dev.ysogabe.ContextCapture`、カテゴリ **triage**（ステップごとの ok / skipped / failed）と **models**
  （モデル・検索の準備、索引の作り直し）。またはターミナルで
  `/usr/bin/log stream --style compact --info --predicate 'subsystem == "dev.ysogabe.ContextCapture"'`
  （zsh では `log` が組み込みコマンドと衝突するので `/usr/bin/log` と書く）。
- 起動直後の流れ（ログ）:
  1. `whisper ready in …s`
  2. `search readiness: preparing` → `triage resumed N records`（未処理のガード・意図が先に進む。索引は `EmbeddingNotReady` で後回し）
  3. `embedder prepared: text …s vision …s`（**初回は ANE の特殊化で 2.5〜3 分**。2 回目以降の起動は数秒〜20 秒）
  4. `search index rebuild: saved=none …` → `search index rebuilt: N records` → `search readiness: ready`
- メニューバーのメニューに、準備中は「検索の準備中…（初回は数分かかります）」、索引の作り直し中は「検索の索引を作っています…」が出る。
  使えるようになると消える。
- データルートに `search-index.json`（索引のシグネチャ。cc-mcp が読む）ができる。

### 0.1 モデルの準備（オンボーディング）— モデルが無い環境で

- [ ] `CC_MODELS_DIR` を空のディレクトリにして起動 → オンボーディングの「モデルの準備」の説明が「合計 約 8GB をダウンロード、変換後 約 5.3GB、
      一時的に 約 13GB の空き」になっている
- [ ] 空き容量が足りない環境（または容量の小さいボリュームを `CC_MODELS_DIR` に指定）で「ダウンロードを始める」→ 何も取らずに
      「空き容量が足りません。モデルの準備に X の空きが要りますが、Y しかありません。あと Z 空けてから…」が出る
- [ ] 十分な空きで「ダウンロードを始める」→ 文字起こし → 検索 → 意図の推定 の順に進捗の項目名が変わる。意図の推定モデルは
      ダウンロード（約 5.8GB。進捗は取得先の大きさから推定）→ 変換（数分・メモリ約 3GB）。完了後に「準備ができました」
- [ ] 完了後、メニューバーに「検索の準備中…」が出て数分後に消える（バックグラウンドで続く。オンボーディングは待たない）
- 既知: d1 の元 checkpoint（`Models/.downloads/`、約 5.8GB）は変換後も残る（計画書 §6 の持ち越し。手で消してよい）

## 1. 意図ラベル（F-09）

- [ ] ⌥Space で「このissueの修正、Claude Codeにやらせて」と話して保存 → 数秒後に Inbox の行に `code` が付く
      （ログ: `<id> guard: ok` → `<id> intent: ok` → `<id> index: ok`）
- [ ] 「PSO のところを明日までに読む」→ `todo` か `research`、日時言及のマーク（📅）が付く
- [ ] 意図が曖昧な発話（「うーん、これ」など）→ 確信度 0.7 未満で「未分類」に入る（Inbox の「未分類」フィルタに出る）
- [ ] 詳細で意図を手で `note` に変える → 注釈を編集して保存 → しばらく待っても `note` のまま（ログ: `intent: skipped manuallyEdited`）
- [ ] 手で変えていない記録の注釈を編集 → 意図が付け直される（ログ: `intent: ok`）
- [ ] 注釈を空にして保存 → 自動推定の意図が消える（未分類ではなく意図なし）
- [ ] アプリを終了 → 起動し直すと、終了前に処理しきれなかった記録が拾われる（ログ: `triage resumed N records`）

## 2. 要確認の表示とマスク（F-10）

テスト用の偽トークン（例: `ghp_A1b2C3d4E5f6G7h8I9j0K1l2M3n4O5p6Q7r8`）を表示したターミナルやテキストエディタで撮る（本物の秘密は使わない）。

- [ ] 保存後、Inbox の行に「⚠要確認」が付き、「要確認」フィルタに出る（初回の OCR はインストール後最初だけ 20 秒前後かかることがある）
- [ ] 詳細を開くとスクショ上の検出箇所が枠でハイライトされ、[マスクした画像を使う] と [確認済みにする] が出る
- [ ] [マスクした画像を使う] → 表示がマスク版（検出箇所が黒塗り）に変わり、要確認が外れる。データフォルダの
      `captures/YYYY/MM/DD/<id>-masked.heic` ができ、元の `<id>.heic` は残る
- [ ] マスク版を拡大して、トークンの文字が上下・左右ともはみ出さず隠れている
- [ ] 別の要確認の記録で [確認済みにする] → 要確認が外れ、元画像のまま（マスク版は作らない）
- [ ] Markdown でコピー → マスク済みの記録はマスク版の画像パスになる。要確認のままの記録は画像のリンクが入らない

## 3. 検索（F-11）

- [ ] 起動直後（メニューに「検索の準備中…」が出ている間）に Inbox で検索 → 文字の一致で結果が出て、見出しの下に
      「検索の準備中のため、文字の一致で探しています」と出る
- [ ] 準備が終わってから（メニューの表示が消えてから）、注釈に無い言葉で探す。例: Zoom の画面を撮った記録を「ビデオ会議の画面」で
      → 見た目で見つかる（注意書きは出ない）
- [ ] 注釈の言葉（例: 「アダプタ」）・ウインドウタイトルでも見つかる
- [ ] 設定で「検索の画像トークン数」を 280 → 70 に変える → メニューに「検索の準備中…」→「検索の索引を作っています…」が出て、
      終わると消える（ログ: `image tokens changed 280 -> 70` → `search index rebuilt: N records`）。`search-index.json` の
      `image_tokens` が 70、`index_signature` が `…/img70` になる。戻すと同じく作り直す
- [ ] 埋め込みモデルを置いていない `CC_MODELS_DIR` で起動 → メニューに「検索: モデルが未準備のため文字の一致で探します」、検索は文字の一致

## 6. MCP（M3、F-12 と受け渡しガード）

[mcp.md](mcp.md) の手順で cc-mcp を Claude Code に登録する（アプリと同じ `CC_DATA_DIR` / `CC_MODELS_DIR` を `-e` で渡す。
既定の場所ならどちらも不要）。cc-mcp は埋め込みを **CPU/GPU で最初の検索時に読み込む**（ANE は使わない）。

- [ ] Claude Code で「Context Capture の inbox を見せて」→ `list_inbox` が今日の記録（注釈・アプリ・URL・意図・要確認フラグ）を返す
- [ ] `get_capture`（include_image: true）で要確認（needs_review）の記録を取る → **画像が返らない**（理由つき）
- [ ] 同じ記録をアプリで [マスクした画像を使う] → もう一度 `get_capture` → **マスク版の画像**が返る（元画像ではない）
- [ ] [確認済みにする] にした記録 → 元画像が返る
- [ ] `search_captures`「ビデオ会議の画面」→ 結果の `mode` が `vector`（cc-mcp の起動後最初の検索はテキスト塔の読み込みで十数秒、
      インストール後の最初の 1 回は 1 分以上かかることがある。Claude Code 側でタイムアウトしないか確かめる）
- [ ] アプリで画像トークン数を変えて索引を作り直している間に `search_captures` → `mode: keyword`、`fallback_reason: embedder_unavailable`、
      cc-mcp の標準エラーに「アプリが検索の索引を作り直している…」（Claude Code の MCP ログ）。終わると次の検索から `vector`
- [ ] `add_note` / `mark_done` が Inbox に反映される（アプリ側で Inbox を開き直す）。削除はできない（ツールが無い）
- [ ] 1 日分の記録を Claude Code から `list_inbox` → 処理 → `mark_done` で片付けられる（M3 の完了条件）
